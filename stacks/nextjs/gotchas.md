# Gotchas — Next.js Stack

> Traps no tool reports. Anything a gate can catch (deprecations, type
> errors, lint rules) lives in the gate instead — see `checks.md`. Each entry
> names the version it was seen on; after an upgrade, re-verify it or delete it.
> `stacks/vinext-cloudflare/` inherits the pnpm, App Router, React, Zod 4,
> Better Auth, and shadcn sections; Prisma 7 and the `next` CLI are this stack only.

## pnpm 11+

- **Build scripts are blocked by default** (`ERR_PNPM_IGNORED_BUILDS`) — the install exits non-zero and names the packages, but writes nothing (pnpm 11.28). Add each to `allowBuilds:` in `pnpm-workspace.yaml` as `true`. The shipped file approves the stack's own: Prisma here, `workerd` and drizzle-kit's `esbuild` on vinext. Approve per package, never blanket-allow.
- **`pnpm deploy` is a pnpm built-in** (workspace deploy), not your script — a `deploy` script runs only as `pnpm run deploy`.
- **A Dependabot PR can fail install with `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`** — its regenerated lockfile took a transitive version under a day old. Until Oct 2026, Dependabot also ignored the release-age gate on pnpm 12 and failed every update on 12.3+ (`ERR_PNPM_STRICT_MIN_RELEASE_AGE_REQUIRES_SAVE`); dependabot-core PR #16376 fixed both. Re-run `gates` once the version is a day old; keep the release-age keys in block-style YAML, which is all that fix reads.

## Prisma 7 (breaking vs 6 patterns)

- **Pin the major: `prisma@7` and `@prisma/client@7`.** Since Oct 2026 npm `latest` for `prisma` is an 8.0 RC while `@prisma/client` is still 7.x, so an unpinned install mixes majors. Prisma 8 is a rewrite (`@prisma/orm-postgres`, Node ≥ 22.18) — adopt it as a decision, never by accident.
- **Install `prisma`, `@prisma/client`, and `@prisma/adapter-pg` at one exact version (`-E`).** `prisma@7.10.0` shipped without the provenance 7.9.1 had, so `trustPolicy` resolves `prisma@7` to 7.9.1 while `@prisma/client@7` gets 7.10.0 — the CLI then generates a 7.9.1 client against a 7.10.0 runtime (Oct 2026; 7.9.1 is the newest set that installs).
- **Config moved to `prisma.config.ts`** (generated by `init`); it does NOT auto-load `.env` — it needs `import "dotenv/config"` at the top and `dotenv` installed as a dev dep. That loads `.env` only: for `.env.local`, call `config({ path: ".env.local", quiet: true })` (`quiet` hides dotenv 17+'s log line). Anything else importing the schema config (scripts) has the same requirement.
- **The generator is `prisma-client` (not `prisma-client-js`)** and outputs TS source into the project (e.g. `lib/generated/prisma`) — gitignore it; create-next-app 16's template already does.
- **Driver adapters are the default: `new PrismaClient()` requires an adapter** — for Postgres, `@prisma/adapter-pg` and `new PrismaClient({ adapter: new PrismaPg({ connectionString }) })`. The generated client's own doc comment shows the exact shape.
- **`adapter-pg` runs on `pg`, and `pg` 8.23 warns that `sslmode=require` weakens in pg 9** — write `sslmode=verify-full` in every connection string.
- **`prisma migrate dev` refuses non-interactive environments** (agents, CI, some shells) — and an `--allow-non-interactive` flag doesn't exist. The workflow that works: hand-write the SQL under `prisma/migrations/<timestamp>_<name>/migration.sql` → `prisma migrate deploy` → `prisma generate`. `migrate deploy` is the officially supported non-interactive command.
- **`prisma migrate diff` prints "Loaded Prisma config from prisma.config.ts." to stdout** (7.x) — it pollutes redirected SQL (`> migration.sql`); strip it (`sed -i '/^Loaded Prisma config/d'`) before `migrate deploy`.
- **Schema edits need an explicit `prisma generate` before building.** `prebuild` runs `tsc` first, so a schema change surfaces as confusing stale-client type errors, not as "you forgot to generate."
- **A running dev server holds the old generated client** after a column rename — writes fail with `ColumnNotFound` even on unrelated fields (Prisma returns the full row). Restart dev after schema changes.
- **`Decimal` fields don't cross the Server→Client Component boundary.** Convert with `Number()` (or format server-side) before passing as props.

## App Router (Next.js 16.4)

- **A `notFound()` after streaming starts returns 200 + `noindex`, not 404** — the first streamed chunk commits the status; `redirect()` mid-stream likewise becomes client-side (bundled docs: streaming guide, "The HTTP contract"). Streaming starts at the first `<Suspense>` fallback, and a `loading.tsx` above the route is one. Detail routes check existence and call `notFound()` before any boundary: no `loading.tsx` above them — move list skeletons into a route group such as `(feeds)`. Share that loader between `generateMetadata` and the page with React `cache()`.
- **Server Actions are dispatched one at a time per client** (16.3+ docs, "Sequential dispatch") — a second action waits for the first, and `Promise.all` over actions runs them in series. Client Components read through GET route handlers (`Cache-Control: private, no-store` for per-user data) with TanStack Query or SWR; Server Actions stay mutations-only.
- **Next 16 renamed `middleware.ts` → `proxy.ts`** (middleware convention is
  deprecated; the file exports a `proxy` function). Optimistic cookie checks
  go there; the DAL stays the real guard. Build output lists it as
  "ƒ Proxy (Middleware)".
- **Auth never goes in layouts** — they don't re-render on client-side navigation, so a lapsed session passes unchecked. DAL is the boundary (`rules/mistakes.md`, official Next.js auth guide).

## `next` CLI (16.4 — this stack only)

- **Killing a backgrounded `pnpm dev` by wrapper PID leaves a zombie
  `next dev` child holding the port** — the next start silently moves to :3001
  and requests to :3000 hit the stale process (phantom 500s, hot-reload
  half-states). Kill with `pkill -f "next dev"` and verify the port is dead
  before retesting.
- **Stale `.next` after deleting or renaming a route:** the generated type validator still references the old file (`TS2307: Cannot find module`). Fix: `rm -rf .next`, rebuild. Applies to any route file move/delete.

## React (19.3, oxlint 1.87)

**Effects sync with external systems — nothing else.** Every other need has a dedicated pattern, and the React Compiler lint (`react(set-state-in-effect)`, see `checks.md`) rejects the commonest misuse:

| Need | Pattern |
| ---- | ------- |
| A value computed from props/state | Derive it during render |
| Reset state when the entity changes | `key` on the component |
| Work caused by a user action | The event handler (debounce with a timer ref) |
| Read an external store (cookies, `matchMedia`, storage) | `useSyncExternalStore` — module-level `subscribe`, cached `getSnapshot`, `getServerSnapshot` for SSR |
| A listener for an element's lifetime | React 19 ref callback that returns its cleanup (stable via `useCallback`) |
| Data | Server Component, or `use()` on a promise created outside render, inside Suspense + an error boundary |

- **Reading a ref during render is rejected** (`react(refs)`). For a stable per-mount value (e.g. a client idempotency key): lazy state init — `useState(() => crypto.randomUUID())`.
- **Each `createContext` lives in its own module**, never in a file that also exports a component — mixed exports break Fast Refresh and duplicate the context in dev.

## Zod 4 (4.6)

- Deprecated v3 forms (`z.string().email()`, `.flatten()`, `.merge()`, `.passthrough()`) fail lint via `typescript/no-deprecated`. Three v4 preferences carry no tag, so no tool flags them: `{ error: "..." }` over `{ message: "..." }`, `z.strictObject()` over `.strict()`, `z.int()` over `z.number().int()` (4.6).
- **An object-level `.refine()` is skipped while any field has an aborting issue** — a wrong type or a missing value (an unset select or number field); a failed `.min()` does not abort. Cross-field errors (confirm password, date ranges) then appear only on a second submit. Pass `{ when: () => true }` and guard the check against partial input so every error shows at once.

## Better Auth (1.7)

- **The CLI is the `auth` package: `npx auth@latest generate`** — `@better-auth/cli` stopped at 1.4. It needs a config that exports `auth` (or a default), and it OVERWRITES the schema file — run it before adding your own models, or list the hand edits to reapply. Chicken-and-egg on fresh Prisma projects: `prisma generate` on the empty schema first so `lib/auth.ts` can import a client, then generate, then `prisma generate` again.
- **With a database adapter, import `betterAuth` from `better-auth/minimal`** — it drops Kysely and its dialects (measured: auth chunk 885 → 788 kB). `auth generate` runs on it too (1.7.7, Prisma and Drizzle adapters).
- **`session.cookieCache` makes `getSession` trust the signed cookie for `maxAge`** — a revoked session keeps passing guards until it expires. Guards pass `query: { disableCookieCache: true }`; display-only reads keep the cache (see `core/auth.md` DAL).
- **The default rate limiter counts in memory per instance** — on serverless (Vercel functions, Workers isolates) limits barely apply. Set `rateLimit: { storage: "database", customRules: { "/get-session": false } }` (the `rateLimit` table comes from the CLI; the rule stops every page load writing a row) and `advanced.ipAddress.ipAddressHeaders` to the platform's client-IP header.
- **`baseURL: { allowedHosts: [...], fallback }`** (1.7) resolves the URL from the request host against an allowlist (`"*.vercel.app"` covers previews) — no per-environment URL variables.
- **Email callbacks return the send promise; set `advanced.backgroundTasks.handler`** (`waitUntil` from `@vercel/functions` or `cloudflare:workers`). With the handler, Better Auth runs the send in the background and logs failures; without it, the response waits for the send, and that timing reveals whether the account exists. Confirm delivery once in the provider's log — background failures are silent.
- **Better Auth email sign-up path is `/sign-up/email`** — route checks using
  `endsWith("/sign-up")` silently never match (tutorial code does this).
  Use `pathname.startsWith("/api/auth/sign-up")`.

## shadcn (base-nova preset, July 2026)

- **base-nova (Base UI) components take a `render` prop where Radix took
  `asChild`** — `<SidebarMenuButton render={<Link href=... />}>children</...>`.
  The type error names only the missing `asChild`, not its replacement. The
  `form` component is `field` under base-nova.
- **Registry hooks can fail the React Compiler lint** (stock `use-mobile` hits
  `set-state-in-effect`) — rewrite them with the effects table above.
